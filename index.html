Step 6 · Figma Import / Handoff
10 / 14
Step 06 / 08 · Browser → Figma

Bring the refined homepage
into Figma.

Once the homepage is approved in code, we import it to Figma as the design source of truth — system, sitemap, and pages, all editable.

01Run HTML.to.design on the approved homepage
02Import design tokens (color, type, spacing)
03Map components to Figma libraries
04Stage the sitemap as Figma frames
05Snapshot every approved page
06Hand off the Figma file to the design team
Code first, Figma second — never the other way around.
Step 7 · Inner Pages & Scaling
11 / 14
Step 07 / 08 · Codify, then scale to every page

Codify, then scale.

<project>-design-system

The implemented system, not the brand guide.

Tokens · Type · Spacing · Color · Components · Hover & focus states · Accessibility rules · Section patterns. Built from the refined homepage code.

<project>-page-builder

How to generate every page after the homepage.

Uses the sitemap, page copy, the design-system skill, and the existing homepage patterns. Same standard, every page.

Page order 1Main → 2Conversion → 3Institutional → 4Secondary → 5Support
The refined homepage is the source of truth. If a skill disagrees with the code, update the skill.
Risks & Mitigation
12 / 14
Six known failure modes

Where projects break,
and how we hold the line.

A gate, a file, or a sequencing rule — for every one.

Risk Mitigation
01 Copy changes after layout Approve copy first, or mark SAMPLE COPY
02 Context lost between sessions Load HANDOFF.md at session start
03 Credit overspend Sonnet for mechanics, Opus only for design calls
04 Inner pages before homepage refined Refine homepage first, then codify into skills
05 Importing to Figma too early Refine in code, import only when stable
06 Images without direction Archive prompts in IMAGE-PROMPTS.md
